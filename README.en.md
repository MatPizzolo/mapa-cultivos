# AI Crop Map

[Español](README.md)

**What was planted in each field, according to two different ways of looking at the same satellite.**

Crop classification over two departments of the Argentine pampa, done twice: once with classical
Sentinel-2 features (bands + indices per phenological window) and once with **AlphaEarth Satellite
Embeddings** (Google DeepMind). The two maps are shown side by side with a draggable curtain between
them, and the metrics below. The question is not "can crops be classified?" — that is settled — but
**how much an Earth observation foundation model actually adds over ordinary feature engineering, on
Argentine crops**.

The project is not the map: it is the benchmark. The map is how it is shown.

---

## What you see

| Interaction | What it does |
|---|---|
| **Curtain** | The two classified maps overlaid with a draggable divider. It is the benchmark made visible: same field, two feature sets, the difference at a glance. |
| **Pixel inspector** | Tap anywhere and it tells you which class each model assigned and what INTA's National Crop Map says at that same pixel. The disagreements are the interesting part. |
| **Disagreement mode** | A layer painting only the pixels where the two feature sets differ, with the per-zone and per-classifier percentage read from `data/desacuerdo.json`. |
| **Case tour** | Chips that jump to concrete disagreement patches, picked with `scripts/06_casos.py` over the largest connected components. So the visitor is not left hunting by eye. |
| **Zone selector** | Río Cuarto (Córdoba) or Pergamino (Buenos Aires). Same legend, same pipeline, two productive realities. |
| **Season selector** | 2024/25 validated, or 2025/26 flagged **unvalidated** — the label shows up as a banner in the interface, not hidden in a footnote. |
| **Metrics panel** | Agreement, kappa and per-class F1 for the four models, read from `data/metrics.json`. A missing value renders as `—`, never as a zero. |
| **Explore** | Draw a polygon and it is classified live against Earth Engine. It is the only thing that needs the network; if it fails, the rest of the app stays whole. Today it returns `503` (see [Status](#status)). |

The growing season runs **July 1 to June 30**. Every temporal window uses that cut, not the calendar
year — with one important exception explained under [Data](#data).

## The benchmark

The obvious setup would compare "Random Forest with bands against kNN with embeddings". That moves
two variables at once: if the embeddings win, you cannot tell whether they won because of the
features or because of the classifier. So all four cells are run:

|  | Random Forest | kNN |
|---|---|---|
| **Classical features** — S2 bands + indices per phenological window (89 features) | A | B |
| **AlphaEarth embeddings** — 64 annual bands, two years (128 features) | C | D |

The result that matters comes from comparing **rows** (what do the embeddings add?), not the
diagonal. Running two more cells costs two runs on the same infrastructure, and it is the difference
between a benchmark and a demo.

### Result of the current run

Agreement with the MNC, 2024/25 season:

| Zone | classical-RF | classical-kNN | embeddings-RF | embeddings-kNN |
|---|---|---|---|---|
| Río Cuarto | 94.3 % | 94.5 % | 91.1 % | 90.6 % |
| Pergamino | 94.7 % | 94.4 % | 93.0 % | 92.9 % |

**Classical features win in both zones**, and a McNemar test on paired hits says the differences are
not noise (`p < 0.05` across all four row comparisons). The gap concentrates where it was expected:
`peanut` in Río Cuarto drops from 0.957 to 0.887 F1, getting confused with soybean. It is the
opposite of what the fashionable approach promises, and it is what gets published.

Two ablations accompany the headline number: using embeddings from a single calendar year instead of
two costs ~4 pp, and a random split inflates agreement by up to 1.4 pp against a spatial-block split —
useful when comparing against published benchmarks, which almost always use random splits.

The full numbers — confusion matrices, per-class F1 with support, intervals — live in
[`docs/BENCHMARK.md`](docs/BENCHMARK.md), regenerated by `make benchmark` and never hand-edited.

### Agreement is not accuracy

INTA's National Crop Map (MNC) is a classification product with its own error, not ground truth.
Against it the project reports **agreement**; the word *accuracy* is reserved for an independent,
hand-photointerpreted set that is not labeled yet. Until it exists, the accuracy tables stay at `—`
and no conclusion rests on them. The distinction is enforced in the code, the docs and the interface
strings. The full protocol — sampling, splitting, what can and cannot be concluded — is in
[`docs/METODOLOGIA.md`](docs/METODOLOGIA.md).

### Reproducibility

Fixed seed (`SEED = 42` in `settings.py`), samples versioned under `data/muestras/`, and every
published number regenerable with one command. `data/metrics.json`, `data/desacuerdo.json` and the
tables in `BENCHMARK.md` are written from the run: if they ever need hand-editing, the bug is in the
script. Changing the seed to improve a number is forbidden — if the result moves across seeds, that
variance is the finding.

## Data

| Collection | Purpose | Since |
|---|---|---|
| `COPERNICUS/S2_SR_HARMONIZED` | Surface reflectance for the classical features, 10 m | 2017-03-28 |
| `GOOGLE/CLOUD_SCORE_PLUS/V1/S2_HARMONIZED` | Cloud and shadow masking. Band `cs`, discarded below 0.60 | 2015-06-27 |
| `GOOGLE/SATELLITE_EMBEDDING` | AlphaEarth embeddings, 64 bands, 10 m, **annual by calendar year** | 2017 |
| National Crop Map — INTA / GeoINTA | Reference layer and basis of the stratified sampling | 2018/19 season |
| Department boundaries — IGN | Geometries for Río Cuarto and Pergamino | — |

**The misalignment worth naming:** AlphaEarth embeddings are annual by **calendar year**, and the
growing season is not. The 2025 embedding mixes the end of the 24/25 season and the start of 25/26
into the same vector. The classical features *are* clipped to the exact season window. It is a real
disadvantage of the embeddings on this problem, and the benchmark measures it (ablation A) instead of
hiding it.

License, resolution and retrieval details for each source are in [`data/README.md`](data/README.md).

## Coverage

Two departments chosen because they read differently, and that difference *is* part of what the
project shows:

| Zone | What characterizes it | What to expect in the classification |
|---|---|---|
| **Río Cuarto department** (Córdoba) | Maize, soybean and **peanut**. Long summer cycles, one dominant crop per season. | Peanut is the hard class: few hectares and a signature close to early soybean. It is where the benchmark is decided. |
| **Pergamino district** (Buenos Aires) | Classic core crop region. Wheat / double-crop soybean is very common. | The `wheat/2nd soybean` class should separate well: two peaks where the others have one. |

Río Cuarto is the default zone because it is the one with peanut, the minority class that separates
the two feature sets. Putting both side by side makes it possible to show on one screen why a Río
Cuarto map does not read like a Pergamino one.

## Class legend

Both zones share a legend so the confusion matrices stay comparable:

`soybean` · `maize` · `wheat/2nd soybean` · `peanut` · `pasture/cover crop` · `non-agricultural`

`wheat/2nd soybean` is **a single class** because in the pampa wheat is almost always followed by a
second soybean crop: splitting them would invent a distinction the pixel does not support. `peanut`
only exists in Río Cuarto, and `pasture/cover crop` does not appear in the 2024/25 MNC for either
zone: both are reported with support 0 and excluded from macro averages rather than filled in with
zeros. Codes, colors and the mapping from the MNC live in `data/leyenda.json`, a single source of
truth; the palette has to survive a color-blindness simulator, and the risky pair is soybean/peanut.

## Stack

- **Compute:** Earth Engine does the sampling, training (`ee.Classifier.smileRandomForest`,
  `smileKnn`) and inference. **No rasters are downloaded.**
- **Orchestration and evaluation:** Python 3.12 managed with `uv`. `earthengine-api` to talk to GEE;
  scikit-learn only to compute metrics over the exported validation table. There is one model, not a
  GEE version and a local version that could drift apart.
- **Backend:** FastAPI, minimal — it serves the frontend, the data JSONs and explore mode. Anything
  that can be static is served static.
- **Frontend:** plain HTML + JS, no framework, with Leaflet vendored for the map and the curtain. No
  build step: what you read in `frontend/app.js` is what runs.
- **The demo does not depend on the network.** Maps are served from precomputed tiles in a GCS bucket
  with long cache lifetimes, limited to zoom levels 9–13. If Earth Engine is down, the only thing
  that breaks is explore mode; the curtain, the inspector and the metrics stay whole. And if the
  tiles do not load either, the viewer explains why instead of failing mute.
- **Deploy:** Cloud Run, same region as the Earth Engine project.
- **No database:** samples and metrics are files versioned in the repo.

## API

Base: `http://localhost:8000`. `docs_url` and `redoc_url` are disabled on purpose: the API is an
implementation detail of the viewer, not a separate product.

| Method | Path | Returns |
|---|---|---|
| `GET` | `/health` | `{"status": "ok", "ee": bool}`. `ee: false` does **not** degrade the app: only explore mode depends on Earth Engine |
| `GET` | `/metrics` | `data/metrics.json` — what the metrics panel draws |
| `GET` | `/leyenda` | `data/leyenda.json` — classes, colors and the mapping from the MNC |
| `GET` | `/zonas` | `data/zonas.geojson` — department boundaries |
| `GET` | `/desacuerdo` | `data/desacuerdo.json` — disagreement percentage per zone and classifier |
| `POST` | `/clasificar` | Explore mode. Today it returns `503` with an explicit message, which the frontend surfaces as a notice |

`/` serves the static frontend and `/tiles` mounts local tiles when that directory exists; in
production the frontend points straight at the bucket and that mount serves nothing.

## Running it

Requires a Google Cloud account with the Earth Engine API enabled and a
[service account registered in Earth Engine](https://developers.google.com/earth-engine/guides/service_account)
— registering it is a separate step from creating it.

```bash
cp .env.example .env          # fill in the variables below
make install                  # uv sync
make dev                      # http://localhost:8000
make test

make muestras                 # 01 — regenerates data/muestras/ against Earth Engine
make benchmark                # 02 — runs the four cells, rewrites metrics.json + BENCHMARK.md
make mapa                     # 03 — exports the classified map (slow: these are GEE exports)
make tiles                    # 04 — GeoTIFF → tiles, uploaded to the bucket
make docker                   # builds the image
```

Scripts `05` and `06` have no `Makefile` shortcut because they take export paths as arguments:
`uv run python scripts/05_desacuerdo.py --exports-dir <path> --corrida <id>`.

### Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `GEE_SERVICE_ACCOUNT` | — | Service account registered in Earth Engine |
| `GEE_KEY_PATH` | — | Path to the JSON key, **outside the repo** |
| `GCS_TILES_BUCKET` | — | Tile bucket, public-read with CORS |
| `MNC_CAMPANIA` | `2024-25` | MNC season to sample against. A parameter, not a constant: if that season is not published, fall back to the latest available |
| `MNC_DIR` | `~/.gee/mnc` | Directory holding the national MNC rasters downloaded from Zenodo. They live outside the repo: no GeoTIFFs in git |

`MNC_DIR` defaults in `settings.py` and is not in `.env.example`. The service account key is in
`.gitignore` and must never enter git under any circumstance.

## Status

Scope is split into layers, with the order of cuts decided in advance:

| Layer | What it includes | Status |
|---|---|---|
| **Floor** | Río Cuarto · 24/25 season · the four cells · curtain + inspector + metrics | Benchmark run and published in `BENCHMARK.md`; the viewer works against the tiles |
| **Layer 2** | Pergamino through the same pipeline | Done: four-cell metrics for both zones |
| **Layer 3** | 25/26 season as an unvalidated inference | The selector exists and so does the "unvalidated" banner; the run is missing |
| **Layer 4** | Live explore mode against Earth Engine | Not implemented. `POST /clasificar` returns `503` with the reason |

Known gaps, all marked `PENDIENTE` in the docs rather than filled in with plausible values:

- **Independent validation:** the ~200 hand-photointerpreted points are missing. Until they exist
  there is no accuracy — only agreement — and no estimated planted area either, because the
  error-matrix correction (Olofsson et al., 2014) is computed against the independent validation.
- **Infrastructure:** the GEE service account and the public tile bucket are still `TODO`s in
  `settings.py`.
- **The MNC's self-reported accuracy** for the 2024/25 season, which is the ceiling on achievable
  agreement.
